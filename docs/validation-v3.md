# v3 SQLite 存档验证

验证日期：2026-09-07。以下是本机 Docker Desktop 和 Chromium 的实际验证，不代表远程生产服务器已部署。

- `npm test`：43 项通过，含 18 项游戏状态 / 战斗规则和 25 项同步时序测试。
- `python3 -m unittest discover -s tests -p test_api.py`：38 项通过，覆盖认证、输入验证、版本冲突、幂等重试、历史恢复、迁移、备份和损坏数据库保护。
- `pnpm test:browser`：桌面及 375 / 430 / 768 px 布局、X 防御姿势、照顾、变身、场景解锁、图鉴、导入导出、跨标签同步及移动端战斗通过。
- `pnpm test:sync-browser`：真实 API 旧存档迁移、断网继续成长、断网刷新、重连补存、恢复码跨设备接回、冲突双方保留、历史回退再恢复通过。
- `pnpm test:battle-save`：真实键盘操作获得胜利，结果页未关闭时 SQLite 已保存 40 经验、20 星光、1 胜、怪兽击败记录及格挡次数；连续刷新无丢失或重复发奖。

三个浏览器流程均使用独立浏览器上下文和隔离测试数据卷，未修改玩家存档。浏览器未出现页面异常。

## 容器与备份实测

测试环境：`COMPOSE_PROJECT_NAME=aoteman-sqlite-integration`，`AOTEMAN_VOLUME_NAME=aoteman_sqlite_integration`，端口 `8789`。

1. 创建合成存档：4,680 经验、42 胜及完整成长字段。
2. 通过 `scripts/backup.sh` 导出一致性快照，验证 SQLite 完整性、全部存档字段、文件权限 `600` 和 SHA-256。
3. 将存档成长到 4,700 经验，执行 `deploy.sh` 备份、重建 API 和网页容器。同一恢复码仍读取到原档案、版本 2、4,700 经验和 42 胜。
4. API 运行时调用恢复脚本，按预期拒绝覆盖。
5. 停止服务后恢复快照，再执行普通 `docker compose down` 和 `deploy.sh`。离线升级前备份成功，新容器读取的整份存档与步骤 1 完全一致，恢复码仍有效。
6. 检查恢复前自动保留的快照，较新的 4,700 经验、42 胜也仍可恢复。

仓库中的 `database/initial.sqlite3` 已验证为结构版本 2 的空模板，三个玩家数据表均为零行。实际数据卷、数据库快照、恢复文件和测试临时文件不进入 Git 或镜像。

## 能保证的范围

正常更新、容器重建及已验证的备份恢复流程会保留存档。首次升级请在原浏览器、原网址打开页面并等待“服务器已保存”，然后下载恢复文件；换设备或域名时用恢复码接回。

同卷快照可处理误操作和版本回退；要应对整台服务器或磁盘丢失，仍需定期把快照导出到独立存储。部署和恢复命令见项目 README。
