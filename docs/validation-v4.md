# v4 成长航线与防御训练验证

验证日期：2026-09-07。以下结果来自本机 Docker Desktop、独立 SQLite 测试卷和 Chromium；不代表远程服务器已部署。

## 成长和旧档兼容

- Node 单元测试 56 项、Python API 测试 43 项全部通过。
- 昵称支持 1–12 个 Unicode 码点；前后端使用同一组中文、表情和非法字符样例，避免浏览器可以保存但 API 拒绝。
- 八项里程碑按真实成长记录判断，领取一次后刷新不会重复发奖。
- 旧 v1 / v2 档增加默认昵称和空领奖记录，其他进度保持；旧客户端 PUT 缺少新增字段时保留服务器对应字段。
- 旧存档样本在 v3 → v4 容器重建后逐字段完全一致：4,680 经验、42 胜、原版本号和恢复身份均保留。SQLite 结构版本继续为 2，未替换数据卷或空库模板。

## 真实浏览器流程

`tests/growth-browser.mjs` 从可见按钮完成起名、喂食和训练：首次喂食领奖后为 10 经验 / 5 星光，导航到特训后为 30 / 10，断网领取特训成长礼后为 40 / 15。断网刷新、联网补存及跨设备恢复均保留名字和领奖记录，不重复发奖；JSON 与恢复文件包含新增字段。

`tests/dojo-browser.mjs` 验证普通、漏挡和完美格挡、重新训练、350ms 窗口、X 双臂可见、暂停、后台与页面卡顿冻结。在真实基地入口连挡三轮后，照顾按钮解锁，本地及 API 的成长计数不变，存档版本不增长，全程没有保存写请求。

`tests/battle-polish-browser.mjs` 验证三怪兽简报、名字安全呈现、能量差额、冷却、真实完美格挡、战后建议、减少重复播报，以及鼠标攻击后的键盘焦点。

原有基地、存档同步和真实战斗奖励浏览器回归继续通过；胜利结果页未关闭时奖励已写入 SQLite，刷新无重复发奖。

已查看桌面及移动端截图。1440 / 375 / 430 / 768 px 页面和成长面板无横向溢出；长列表中的关闭按钮保持可见，训练及战斗支持触摸和键盘。验证过程没有页面运行异常。

## 复现

按 README 启动独立测试环境，避免把合成玩家写入试玩数据库。设置 `BASE_URL=http://localhost:8789` 后执行：

```sh
npm test
npm run test:api
npm run test:browser
npm run test:sync-browser
npm run test:battle-save
npm run test:growth
npm run test:dojo
npm run test:battle-polish
```

默认本地试玩地址仍是 `http://localhost:8787`，真实成长数据库继续保存在 `aoteman_data` 数据卷中。更新使用 `./deploy.sh`，正常迭代无需删除数据卷。
