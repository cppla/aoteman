# v5 濒危援护与双人战斗验证

验证日期：2026-09-07。验证使用本机 Docker Desktop、独立 SQLite 测试卷和 Chromium；不代表远程服务器已经部署。

## 援护规则

Node 单元测试 **71 项**、Python API 测试 **43 项**全部通过。其中新增 15 项援护测试，覆盖：

- 三种难度的 30% 生命门槛、10 光能下限、耗尽光能、每场只召唤一次。
- 登场打断正在蓄力的攻击、向上取整恢复 25% 生命；3 秒护盾到期边界准确，免伤不会虚增格挡或光能。
- 迪迦独立出拳和发射光线，与玩家攻击共同扣除同一怪兽生命；联合攻击消耗 30 光能，造成 54 伤害，有独立及共享冷却。
- 暂停冻结登场、自动攻击、护盾和联合技能；不同帧长得到同一事件序列。
- 同刻攻击时伙伴优先，伙伴补上最后一击可阻止怪兽的致命攻击；实际伤害不超过剩余生命，胜负只结算一次。
- 失败、撤退后伙伴停止行动；快照修改不会污染战斗中的计时。

## 浏览器实战与存档

`tests/ally-browser.mjs` 在独立服务 `http://localhost:8789` 创建合成玩家，通过正常按钮和键盘操作战斗。实战部分没有注入生命、能量、引擎状态，也没有直接向 API 写奖励。

一次已验证的流程中，玩家先出两拳保留 18 光能，承受真实攻击至 **42/150** 生命。在怪兽下一次蓄力期间按 6，蓄力被中断，生命恢复到 **80/150**，光能归零。暂停时伙伴不造成伤害，恢复后迪迦自动打出 12 点伤害。玩家继续积攒光能并发动联合光线，两位角色同时进入发射姿态，怪兽实际减少 54 点生命。

取胜时，结算弹窗仍然打开，SQLite 已保存 **40 经验、20 星光、1 胜**及击败怪兽记录；刷新页面不会重复奖励，也不会丢失成长。

原有 `tests/battle-save-browser.mjs`、`tests/battle-polish-browser.mjs` 和 `tests/browser.mjs` 回归通过，涵盖 X 防御、能量差额、快捷键焦点、暂停、怪兽简报、战后建议，以及照顾、跨标签同步、导入导出和手机布局。

## 角色与界面

迪迦使用独立 SVG，具有红紫战衣、金色胸甲、独立手臂及蓝色计时器。待机、出拳、光线、防御和胜利姿态已在浏览器中检查；两名角色的 SVG 标识不冲突。

375、430、768 px 下两名英雄占据不同位置，战斗面板没有横向溢出，联合按钮保持可触摸尺寸。移动布局的快速准备使用独立测试页面和引擎公开的时间推进方法，不修改玩家存档；已目视检查角色和按钮。额外测量确认桌面及上述三种宽度下，两束光线起点均贴合实际 SVG 手腕并收束到怪兽胸前；暂停联合攻击超过 1 秒，两束光线特效仍保留且不继续计时。

## 复现

按 README 启动独立测试服务，再执行：

```sh
npm test
npm run test:api
BASE_URL=http://localhost:8789 npm run test:browser
npm run test:battle-polish
npm run test:battle-save
npm run test:ally
```

截图与实战摘要保存在 Git 忽略的 `test-results/ally/` 中。新增机制只改变单场战斗，沿用现有胜负奖励及存档 API；SQLite 结构版本保持 2，运行中的数据库不从仓库模板覆盖。
